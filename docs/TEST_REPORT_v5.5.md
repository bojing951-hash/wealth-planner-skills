## 具体防错案例说明

1. PF 自报银行收款 $24,000/月作为 `USER_REPORTED` 暂定外部现金，未查实流水情况下 `documented_external_received=0`；持仓券商的 $15,000–70,000 月度利润区间不能再次当作银行新现金，但其账户 **净权益如确有受益所有权则应纳入资产表**。
2. 当前现金支出 $3,950/月，之前尚未再次确认的旅游支出 $700/月。情景保留两版（$3,950 和 $4,650），没有默默丢失历史开支或假装一直持续。
3. 12个月核心现金缓冲 $47,400／含旧旅游消费 $55,800 都只是演示目标；现有自由现金未知时，系统输出储备缺口和生存月数 **UNKNOWN**，不声称“只需一个月即可备足”。
4. 税负及经营成本未知时，`conditional_new_long_term_cashflow_ceiling` 保持 `null`；系统不把 35%–45% 当成税法，也不据此硬性停止所有风险/现金流分析。
5. 借款月供完整计入现金流；它包含利息和本金偿还，不能将其经济意义全部表述为消费。券商资金划回银行是资产位置变化，不是新增净资产。
6. 在用户提供现金、券商NAV和车贷本金时，计算 `known_components_subtotal_NOT_TOTAL_NET_WORTH`，**始终不声称这是完整家庭净资产**，因为缺少其它资产、预留税款和负债。

## 上线与隐私限制

- 新增强化了专业咨询的指导流程，但 **不会启动自己的LLM Agent，也不在后台持续运行**。宿主负责搜索、核对和用户审批。
- 所有公开合成测试数据都不包含实际用户账户资料；不应将真实交易、银行资料写入公开Git仓库。
- Python加密记忆为独立可选组件；本次不宣称新一轮跨系统密钥/ACL审核通过。
- GitHub `main` 写入权限本轮工具不可用，交付为本地发布候选源码与可安装Skill压缩包；**不声称已推送 v5.5**。
