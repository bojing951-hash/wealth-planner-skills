# 从可移植 Skill 升级为完整财务规划 Agent：技术路线

## 模块与职责

```text
用户（文字/安全导入本地CSV等）
   │
   ▼
LLM主编排器 ──> SKILL.md（标准操作流程、限制与证据层级）
   │
   ├── [确定性数据校验] → 真实到账收入、资产所有权、币种、债务一致性
   ├── [现金流/负债引擎] → 月度预算、储备、偿债模拟
   ├── [目标复利引擎] → 可行性、缺口、三情景
   ├── [研究证据检索] → 金融研究、官方规定，附来源+更新时间
   ├── [未来独立风险引擎] → 收益路径、相关性、尾部、收入共振
   └── [未来只读MCP工具] → 财务账本，不自动转账或交易
   │
   ▼
说明书式报告：事实/模型/证据/假设/行动/局限性
```

### 为什么先做一个Skill？

它用一个 `SKILL.md` 汇总知识调用逻辑，安装路径简单，跨模型容易迁移。脚本随 Skill 一起部署，不会出现“只下载了提示词却丢了算法”的问题。过早做多个重叠 Skill，会使版本同步和互相调用的责任边界变得复杂。

### 为什么不直接写成单个超长 Prompt？

- 长Prompt无法可靠替代可复算金额计算。
- 投资大师建议有数学、样本、时代背景及适用条件差异。
- 资产配置需要额外风险/期限/合规数据，不能单靠月薪确定。
- 金融账户信息不应该变成公开仓库里的提示词上下文。

## 在未来何时拆分为多个 Skills？

只有当某模块能独立维护、独立测试、有稳定的输入输出契约时再拆：

- `cash-flow-audit`：收入和现金流核验；
- `goal-feasibility`：目标缺口与复利；
- `portfolio-policy`：投资政策与成本；
- `risk-and-stress-test`：收入/市场联合模拟；
- `evidence-and-compliance`：研究/监管检索和溯源。

**现在优先保证一个能安装、能运行、能测试的Skill**，随后再把共用引擎抽象成可由多个 Skills 调用的独立Python包或MCP服务。
