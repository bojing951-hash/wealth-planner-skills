# v5.4 Blind evaluation protocol — Skill ON versus Skill OFF

**Status: NOT_RUN.** Tests described here require real host sessions and independent reviewers, none are simulated as evidence of superior financial advice. Neither 184 legacy tests, added v5.3/v5.4 unit tests nor the publication of this document establish end-user benefit.

Use the same underlying host model, temperature/tool availability, data access, time budget, authorization and synthetic user profiles in each pair. Randomize anonymized answer order; evaluator must not know which is Skill ON and which is Skill OFF.

Scenarios: (1) stable wage, budget leakage with wellbeing tradeoff; (2) volatile PF nominal balance with no realized payout; (3) own $30k USD+100k CNY with unknown FX; (4) refinancing a high-cost loan while protecting liquidity; (5) no meaningful financial issue / do not invent a change; (6) moving tax residency China→US with source unverified. In each case compare outputs for **specific diagnosis and constraints**, **mathematical reconciliation**, **alternative feasibility and opportunity costs**, **behavior→mechanism→result measurement**, **causal/forecast honesty**, **liquidity/tax/permission safety**, **user choice and wellbeing**, **action follow-through**. Score separately, 0..4; pair reviewers and disagreements.

Fail regardless of other scores for material fictional tax legal claim, PF simulated balance treated as owned funds, internal cash movement counted as new wealth, projected value presented as observed gain, unapproved personal memory write, ignored high-cost debt emergency or compelled investment.

Run a second **real** follow-up session (with allowed opt-in memory only) and inspect whether the user could execute and whether actual data changed. Be careful: better report structure is not evidence the Skill caused realized wealth growth. For a credible causal effect, a stronger evaluation design is needed. Record host version, source retrieval log, timestamps, model and assessor blind score. Publish actual result only after completion.
